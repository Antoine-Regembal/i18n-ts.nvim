1. INTRODUCTION                                                *i18n-ts-intro*

Shows the translation next to every `t('key')` call, reports missing keys,
jumps to definitions, completes keys and adds new keys to every locale file.
Works with JSON translation files (vue-i18n, i18next, next-intl, ...).

Requires Neovim >= 0.10. Optional: ripgrep, snacks.nvim, blink.cmp.

==============================================================================
2. SETUP                                                       *i18n-ts-setup*

>lua
    require("i18n-ts").setup({})
<
Every option, with its default, is listed in the README. Configuration is
merged in this order: defaults, |i18n-ts.setup()| options, the project's
`.i18n-ts.json`, then `projects[root]` from your setup.

                                                          *i18n-ts-project-file*
`.i18n-ts.json` at the project root may set `sources`, `locales`,
`default_locale`, `namespace_separator`, `default_namespace`, `functions` and
`patterns`. It is read as JSON and never executed; `add.format_cmd` is ignored
there.

==============================================================================
3. PROJECT DETECTION                                         *i18n-ts-project*

Root: the first of `root_markers` (`.i18n-ts.json`, `.git`, `package.json`)
found upwards from the buffer.

Sources: `sources` when set, relative to the root, with `{locale}` and an
optional `{namespace}` placeholder. Otherwise directories named `locales`,
`locale`, `i18n`, `lang`, `langs`, `messages` or `translations` are searched
up to `auto_detect.depth` levels, skipping `auto_detect.skip` and hidden
directories.

Run `:checkhealth i18n-ts` to see what was detected.

4. COMMANDS                                                 *i18n-ts-commands*

:I18n [info]            Root, sources, locales, key count, load errors.
:I18n def               Jump to the key under the cursor.
:I18n show              Float with the key in every locale.
:I18n next              Display the next locale.
:I18n keys              Key picker. <CR> jumps, <C-e> edits, <C-x> removes,
                        <C-y> yanks, <A-i> inserts.
:I18n edit [key]        Edit the key in every locale, see |i18n-ts-editor|.
:I18n translate [key]   Machine-translate the missing locales of a key.
:I18n add [key]         Add a key to every locale file.
:I18n remove [key]      Delete a key (or an object) from every locale file,
                        after confirmation. Warns when it is still used.
                        Parents left empty are removed (`remove.prune_empty`).
:I18n usages [key]      Usages of a key (ripgrep).
:I18n toggle            Hide / show translations and diagnostics.
:I18n reload            Re-read configuration and translation files.

                                                              *i18n-ts-editor*
The editor float has one line per locale, the default locale first, and each
line holds only the value. Changes that add or remove lines are rolled back,
so the float always has one line per locale.

    dd                  Clear the value.
    <Tab> <S-Tab>       Next / previous locale (normal and insert mode).
    <CR> (insert)       Next locale.
    o O J               Disabled.
    :w                  Save the changed lines, add the filled-in locales.
    <CR> (normal)       Save and close.
    <C-t>               Save, then translate the empty locales now.
    q <Esc>             Close without saving (empty locales are still
                        translated from the saved default value).

Emptied lines are left unchanged. Newlines in values are shown as `\n`.

                                                           *i18n-ts-translate*
With `translate.provider` set ("claude_code", "anthropic", "deepl", "command"
or a Lua function), closing the editor fills the saved locales still empty,
translated from the saved default locale value. `:w` only saves. To translate
while the editor is open, press <C-t> or run `:I18n translate`. Values that
already exist are never re-translated. The source text is sent to the
provider. Translations run in the background: closing the editor doesn't stop
them, the
inline preview of the key shows a "translating…" indicator until the result
is written, and locales filled in meanwhile are never overwritten.
"claude_code" runs `claude -p` and reuses the Claude Code login, with no API
key. For "anthropic" and "deepl", API keys are read from the environment
variable named by `api_key_env` and passed to curl on stdin. `translate`
cannot be set from `.i18n-ts.json`.

                                                        *i18n-ts.definition()*
require("i18n-ts").definition()
    Jumps to the key under the cursor. Returns `false` when there is none, so
    it can fall back to |vim.lsp.buf.definition()|.

==============================================================================
5. COMPLETION                                             *i18n-ts-completion*

blink.cmp provider:
>lua
    providers = { i18n = { name = "i18n", module = "i18n-ts.blink" } }
<
Keys are offered only inside a translation call.

6. HIGHLIGHTS                                             *i18n-ts-highlights*

I18nTsTranslation       Inline translation. Links to |hl-Comment|.
I18nTsMissing           Links to DiagnosticWarn.
I18nTsLocale            Locale labels in the editor. Links to |hl-Label|.
I18nTsPending           Translation in progress. Links to DiagnosticInfo.
